# 第 4 步：引擎标定（作战与指挥拆开，两种模式）

生成于 2026-09-11。只读引擎、只做离线模拟，没有改 match.ts / arena.ts。

## 代码路径：一名主指挥的价值现在走哪几条线

- `match.ts buildLineup`：队伍强度 `common = base + iglBonus + chem + coach + comp + mapPref + util + …`
  - `base` = 五人 `effectiveRating`（= overall × 状态/士气/疲劳）的加权均值，权重按强弱排 [1.24, 1.1, 1.0, 0.9, 0.76]（和 5.0）。**卡面总评走的是这条线。**
  - `iglBonus = (主指挥.attrs.igl − 60) × 0.09`，中局另有 `(igl − 60) × 0.06`；主指挥 = 俱乐部指定的 `team.igl`，否则 `isIgl` 里指挥属性最高的一人（`roster.ts callerOf`）。**指挥属性只走这条线，只有一个人走。**
- `arena.ts seatSquad`：落座时把卡的 `rating`、`attrs` 克隆成球员，属性向 70 压缩 0.6 倍、总评向 80 压缩 0.6 倍，再走同一套 `buildLineup`。
- 因此若卡面总评 = (1−w)·作战 + w·指挥分，而引擎仍把卡面总评读进 `base`、又按 `attrs.igl` 加 `iglBonus`，指挥的价值就走了两条线。这是路径事实，与胜率相加与否无关。

## 拆分方案（待实现，未改引擎）

1. `base` 读**作战分**（candidate combat，按 scale_v1 映射），不读卡面总评。经理模式球员的 `overall` 与卡面总评分离：卡面 = (1−w)·作战 + w·指挥分 + 荣誉，引擎用作战。
2. `iglBonus = k × (主指挥的指挥分 − 70)`，指挥分 = 指挥能力 z 映射到作战同尺（先验 70）。k 的标定：卡面上 w 表示「指挥分高 10 分 ≈ 总评高 w×10」；引擎里一人总评 +1 ≈ 0.2 强度，故 w=.35 时指挥 +10 应值 ≈ 0.7 强度 → k ≈ 0.07；w=.25 → 0.05；w=.45 → 0.09（现值）。三档都在现引擎系数附近，说明现引擎对指挥的定价与 w≈.45 相当。中局项按同比例（k×0.67）。
3. 一队仍只有一人提供指挥贡献（`callerOf` 不变），其余人的指挥分不进比赛。
4. arena 路径不需要单独系数：压缩对两条线同比例。但 arena 的落座读的是卡的 `rating`、`attrs`，卡数据要同时携带作战分与指挥分两个字段。
5. 默契、阵容、教练维持现状；「当前队伍的熟悉程度」按你的要求归入默契/适应，不进指挥分。
6. 荣誉：不进 `base`、不进 `iglBonus`。是否以别的方式进比赛（例如大赛心态）是产品规则，本报告不定。
