# 数值 v2 与天梯 BO5：第一阶段验收报告

核验日期：2026-09-18。本文基于当前工作区和已有原始输出，不代表已部署线上。

## 结果与方法

已直接读取 raw/confirm_*.json：161 个互不重复的测试组合，共 1,051,000 场系列赛；不是 105 万种阵容，也不是全部 BO5。训练拟合与确认脚本分开，确认种子独立。原始表见 [confirm_tables.md](confirm_tables.md)。

数值版本 BALANCE_VERSION=2；强度差为 `E(d)=0.36d+0.56*[softplus((d-2.9)/0.5)-softplus(-5.8)]`。E(0)=0；导数为 `0.36+1.12*sigmoid((d-2.9)/0.5)`，始终为正且连续，因此曲线连续单调，不存在整数跳档。保留未取整综合分、对称强度映射和完整回合模拟。

## 独立核实回归

check_balance_v2 和 check_card_score_odds 的日志均已结束 EXIT=0。另核实 gap_curve、club_balance、cup_fairness、cup_double、cup_path、ladder、ladder_match、ladder_pin、leagues、power_growth、arena_report 共11份日志 EXIT=0。

接手后重新执行 `node --import tsx scripts/check_ai_growth.ts`，EXIT=0：三种子十赛季顶尖AI能力峰值93.34、93.06、93.12；联盟中位数未持续通胀；没人越过潜力或99。未修改断言。初次 npx tsx 因沙箱禁止IPC创建失败，改用node入口后正常通过，该环境错误不属于玩法失败。

以上旧日志证明各脚本当时通过，不能替代最终集成后的完整重跑。天梯BO5按整场结算一次，生涯/首尔征途隔离仍应纳入最终综合回归。

## 接手后的真实 PostgreSQL 验证补充

已在临时 PostgreSQL 18 的独立自动销毁数据库运行6项测试，最终 `logs/real_pg_v4.log` EXIT=0：旧load迁移CAS、请求幂等/并发/响应丢失/墓碑、市场只读及有界结算与故障回滚、旧杯赛并发推进、14买家争一张卡与12人争末席、低序号延迟事务汇总不漏记。测试使用真实多连接池，无生产连接。

最初运行发现并修正测试适配问题（public schema探测、postgres.js JSON参数与故障注入、临时文件模块格式、worker import.meta位置）；市场墓碑检查改为有界等待异步维护完成，业务不重扣断言保留。前几版日志仍保留作为排查证据，最终结论以v4为准。此结果覆盖数据库正确性，不代替真实混合负载容量或手机布局验证。
