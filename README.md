# VAL MANAGER · 无畏契约电竞经理

> 猪之家 制作

一款浏览器端的《无畏契约》（VALORANT）电竞经理模拟游戏。你执掌一支战队，管理阵容、
战术、训练、转会与财务，带队征战 VCT 四大赛区、国际赛与次级联赛。

灵感来自 Football Manager 与 Steam 上的 CS2 电竞经理，玩法形式参考了 B 站的
《无畏人生模拟器》，但**数据完全独立**，全部来自专业电竞数据网站。

## 真实数据，没有虚构人物

游戏里的每一位选手都是真实存在的职业选手。没有任何"生成"的假名字。

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| 战队、阵容、国籍、位置 | [vlr.gg](https://www.vlr.gg) | VCT 2026 赛季 |
| Rating / ACS / K/D / KAST / ADR / KPR / APR / 首杀率 / 爆头率 | vlr.gg | 真实赛季统计 |
| 选手真名、生日 | [Liquipedia](https://liquipedia.net/valorant) | 官方 MediaWiki API，318/340 人 |
| 主教练、助教、IGL（指挥） | Liquipedia 战队 infobox | 49/53 教练，47/53 IGL |
| 一级联赛参赛名单 | vlr.gg 赛区筛选 + 赛事页 | 四大赛区各 12 队，逐队核对 |

### 能力值看四件事，不只是数据高低

单一的生涯平均值分不清"三年都稳"和"一路下滑"，也分不清突破手和控场。现在能力值综合：

1. **近期权重更高**（2026 : 2025 : 2024 = 3 : 2 : 1）——Lysoar 从 R 0.82 → 0.98 → 0.99，
   压平后只值 0.95，按近期加权才反映他现在的水平
2. **大赛表现**——Champions / Masters 上相对自身基准的发挥，另计加成（最高 ±5）
3. **样本量**（见下）
4. **按位置计权**——突破手看枪法/反应/残局，控场看道具/意识/协同。原来一套通用权重把
   41% 压在意识、道具、协同上，等于按"助攻多不多"给突破手打分

数据来自 2024–2026 三个赛季**全部 45 场 VCT 赛事**的分场统计（2739 条），
所以分年、分级别都是真实记录，不是从一个平均数倒推的。

### 样本量也算数

一名替补顶上打了一张图，数据可能很好看——但那不是他的水平。所有统计量都按
**回合数向联盟均值收缩**（400 回合算一半可信，4000 回合算九成），全联盟有 52 人因此被拉回。
自动首发还会**额外折算样本不足的人**：XLG 的 Sharks 只有 119 回合（NoMan 有事，他替补上场），
原来会顶掉打了 8031 回合的真首发 Lysoar，现在不会了。

### 能力看生涯，状态看今年

能力值取自选手的**生涯全时段**数据（vlr.gg 的 `?timespan=all`，949 名选手、回合数中位 5801），
今年的表现则换算成**初始状态**。原来两者都用 2026 单季，结果是"某人今年打得差"被建模成
"某人变弱了"——ZmjjKK 2024 年拿冠军、生涯一直不错，只因 26 年球队下滑就被压低了上限。
现在他是**能力 80 / 状态 63**：一个正在低谷的强者，而不是一个变差的人。全联盟有 16 名
能力 ≥80 但状态 ≤50 的选手，反过来也有今年爆发的。

### 能力值是怎么来的

八项能力值不是拍脑袋定的，而是由上面那些**真实的每回合数据**按分位映射得出：

| 能力 | 来源 |
| --- | --- |
| 枪法 | ACS、ADR、爆头率 |
| 反应 | 首杀率（FKPR）、每回合击杀（KPR） |
| 意识 | KAST、首死率（越低越好） |
| 道具 | 每回合助攻（APR）+ 位置特性 |
| 残局 | Rating、K/D |
| 协同 | KAST、APR |
| 沟通 | KAST + 位置特性 |
| 指挥 | APR、KAST + 位置特性；**指定指挥以球队实力托底**——冠军指挥的价值恰恰不在个人数据里（Boaster 光看数据只值 71），强队的指挥就该是强指挥，弱队相对低，已在阵容里高于球队水准的不动 |

因为单项分位取平均会把所有人压向中游，每一项还会与选手的整体 Rating 分位加权混合
（真实能力本来就是相关的：顶级选手多数项都强），这样才能还原出真实的能力梯度。

### 人工核验覆盖表

vlr 的位置筛选给的是"出场最多的位置"，这对两件事不够用：**谁是 IGL**（vlr 根本不发布），
以及**谁是真正的自由人**。脚本只能靠推断，而推断会错——例如 PRX 会被推成 invy 指挥、
something 兼哨卫，实际是 f0rsakeN 指挥且他才是决斗/烟/哨/先锋全打的自由人。

因此有一层 `data-raw/overrides.json`：**手工核验过的真实信息，优先级高于推断**。
没列进去的队伍保持推断值——**宁可留空也不猜**。

**同名不同人**是这套抓取最隐蔽的错误。Liquipedia 按 ID 建页面，而 ID 会撞：
叫 `Neon` 的页面是一名菲律宾选手，VCT 美洲的 Neon 是阿根廷的 Bruno Rodríguez，
2008 年出生。我们抓了另一个人的页面、发布了他空白的生日，于是游戏把一个 17 岁
的人估成了 27 岁——同样的错误还有 20 处。vlr 和 Liquipedia 都记国籍，两边一对
就能发现，不用重抓任何东西：**对不上就整页丢弃**，宁可未知也不安别人的身份。
其中 9 人在消歧页（`Neon (Argentine player)` 这类）上找到了正确的本人，已修正；
其余 12 人 Liquipedia 上确无对应页，保持未知。审计里有一条专门守这个。彻底的解法是抓 vlr 每个位置的真实回合
分布，用实际英雄池宽度判定自由人；在那之前，发现错的就往这个文件里加。

**估算的部分**（并已在界面中标注）：合同年限、薪资、俱乐部预算与训练设施等级——
这些是游戏平衡所需，公开数据里没有。Liquipedia 未收录生日的选手，年龄按真实
VCT 年龄分布推算，选手详情页会显示"（推算）"。缺失的主教练**留空**，不会用虚构人名补齐。

合同年限是 1~4 年，但**不是每人独立掷一次**：那样掷出来的结果是全联盟三分之一的合同
在同一个冬窗到期，FURIA 六个人里五个一起到期——现实中没有俱乐部会走到这一步，而且
每次续约都要花行动点，玩家根本无从补救。所以年限是按俱乐部整体发放的：四种年限轮着发，
发放顺序按"这家俱乐部最想留住谁"排——年轻有上限的排前面，老将排后面。因此七人阵容
同年到期的**最多只有两人**，最长的那份合同也一定在值得留的人身上。

## 玩法

- **四大赛区一级联赛**：VCT Americas / EMEA / Pacific / China，各 12 支合作战队
- **次级联赛**：Challengers，四大区共 30 支真实战队（美洲 8 / EMEA 8 / 太平洋 7 / 中国 7），
  冠军通过 Ascension 升入 VCT，**同时该赛区冠军点最少的一级队降级**——每季每区固定
  换一支，联赛规模始终 12 队。次级队的董事会目标结算在自己的两个赛段上，不是 VCT 的赛段

  > **一处归属是我们安排的，不是真实赛事归属。** Weibo Gaming 2026 年打的是国内赛事
  > （China National Tournament、China Evolution Series），既没打 VCT CN，也没打
  > Challengers China。俱乐部和五人名单（AcMe / Yoyo / Satoshi / heybay / Leav3u）
  > 与其他队一样来自 vlr.gg 的真实数据，但**把它放进 Challengers China 是本作的编排**。
  > 之所以在这里，是因为 vlr 的中国区数据源只收录晋级的 8 支队，WBG 止步于 10–11 名。
- **完整赛季日历**：季前 → Kickoff → Masters I → Stage 1 → Masters II → Stage 2 →
  Champions → 休赛期，共 336 天
- **可选规则「限制外援」**：新建生涯时勾选（或在系统页随时开关）。每支俱乐部最多
  **两名来自其他赛区的选手**（按国籍判定，含替补），AI 俱乐部同样受限。只限新引进，
  已有阵容不拆散；出身按国籍判定，没有国籍记录时以选手档案显示的赛区为准——规则和界面永远说同一句话。
- **阵容管理**：首发五人、位置搭配（缺控场/哨卫会有实打实的惩罚）、体能与伤病。
  要凑齐的是**决斗者/先锋/控场/哨卫四个位置**——`自由人` 不是第五个位置，而是"没有固定位置"，
  凑齐四个位置后第五人是谁都不扣分；一个人能兼两个位置算加分。
  首发里**没有指挥**是最贵的一种排法（攻防各 −4、中局 −3，比缺任何位置都贵），
  阵容页会直接点名说谁在替补席、谁伤停到几号，并给出一键任命——**指挥权可以随时交给
  队里任何人**（选手详情页也有入口）。从健康的现任手里拿走会伤他士气；他伤停时交出去，
  他自己也觉得是明智的安排
- **战术**：节奏、道具、侵略性、中局应变四条滑杆，在**每场比赛开始前**设置，观战时**叫暂停还能临场改**；
  配合地图熟练度影响 BP 与胜负
- **训练**：个人专项 + 团队训练同时生效，按周结算。主训练（跑图 / 教练复盘 / 练新英雄）
  三选一，**双排练**可与之并行；练新位置是按熟练度累积的长期项目，约半个赛季才能兼任
- **选手信任**：每名选手对经理有独立的信任度，和士气、不满是三条不同的线——士气是这周的心情，
  不满是"承诺的位置没给我"，**信任是对你这个人几个月下来的判断**。压榨体能、堆商务活动、
  状态好却被拉下首发、卖掉他的好友，都会掉信任；而信任**易失难得**（收益随信任升高递减）。
  信任低会直接让续约谈不成
- **更衣室**：每两名选手之间有独立的关系值，**开局由真实数据决定**——共事时长（Liquipedia
  转会履历）、国籍、位置搭档、年龄与性格。同队队友开局都在 40~70 这一档——他们本来就每天一起训练，
  不该有人一上来就跟队友结怨。EDG 四年老搭档 CHICHOO×Smoggy 是 68，2025 才加盟的
  Jieni7 与他们是 51，队内极差十几分而不是四十分。之后赢球让全队更亲近；输球时打得好的人会
  记恨打得差的人，且**矛盾会滚雪球**。关系差会直接拉低比赛中的团队默契，双排练是主要修复手段
- **建设俱乐部**：训练设施可以花钱逐级升级；教练组可聘请**主教练 / 助理教练 / 数据分析师**，
  人选是各队真实的助理教练。发出报价后对方 1~7 天内答复，可能拒绝；换主教练时原主教练
  转任助教而不是消失。助教加成「培养」，分析师加成「战术」。
  **数据分析师是另一批人**，不与教练共用人才池——全世界只有 5 名在册分析师（vlr 不标注这个
  职位，Liquipedia 上有记录的就这几个，本作不编造真人）。正因为少，**每人各管一件事**：
  图池分析（跑图收益 +60%）、对手研究（比赛战术加成）、数据建模（潜力看得更准）、
  经济分析（道具与经济）、复盘专家（教练复盘收益翻倍）。签谁取决于你缺什么。
  想要**别队在任的主教练**要走两步：先付补偿金请求对方俱乐部放人（可能被拒），
  获准后再和本人谈薪资——本人也可能不来。声望低就得溢价
- **转会**：转会窗口、报价谈判（俱乐部要价 + 选手意愿两道关）、挂牌、解约。
  想要的人多半既没挂牌也不是自由人，所以可以**先问价**：花 1 点行动力向对方俱乐部打听，
  2~5 天后同时得到两件事——**他们真正的要价**（核心球员溢价可达一倍）和**本人愿不愿意来**
- **财务**：赞助、奖金、薪资、运营开支，董事会信任度。**薪资是最大的一笔开支**（约占赞助收入
  一半），所以养一支七人豪华阵容是要还的：全联盟 48 支一级队里常年有十来支贴着亏损线，
  一个赛季的结余大约够买一名顶级球员。次级联赛的运营开支只按一级的 35% 计，
  升降级时赞助合同会重新议价——升上去是一笔横财，掉下来就得先把薪资压下来
- **商务**：既可以接别人的邀约（粉丝见面会 / 品牌活动 / 校园行 / 拍摄 / 直播），也可以
  **主动出击**——自己去谈赞助商，或自办开放日 / 训练营 / 观赛派对 / 周边发售。自办要先垫钱，
  回本取决于俱乐部声望。选手还能签**直播合同**（2~3 个月一签，到期自动结束、可重新谈）：稳定被动收入，
  代价是持续掉体能。
  邀约给的是一个**日期窗口**而不是固定某天，你在窗口内挑一个没有比赛的日子——
  否则一份正好撞上比赛日的邀约就等于作废。所有商务的共同代价是选手的时间——
  **出席一天，这一周的训练收益就少 25%**，四天归零
- **经理天赋**：开局 8 点，分配到训练 / 谈判 / 战术 / 球探 / 体能 / 商务 / 更衣室 / 青训。
  8 点不够样样精通，每一项都接到了真实效果上——其中**球探**不改数值，改的是你能看多准：
  球探低时选手潜力只显示成一个区间（如 77~95），点满才显示确切数字
- **经理求职**：不只是等别人来挖你——「经理」页面可以**主动向任何愿意接你电话的球队投申请**。
  战绩不佳的球队最容易点头，一切顺利的球队最难进（没人要走），要价太高会被拒，3~10 天答复。
  你自己也有合同：可以跟董事会谈涨薪，**手上有别队邀请时最好谈**，刚被警告过就别开口
- **经理生涯**：出身背景决定起始声望与可执教的球队；冠军和超额完成赛段目标会提升声望，
  声望越高，越强的俱乐部会主动发来执教邀请，选手谈判时也更容易被说服。
  顶级豪门只能靠成绩“打”过去，不能一开局就选
- **比赛模拟**：BP → 逐图 → 逐回合，含经济系统（eco / force / full buy）、
  攻防转换、加时，并生成完整数据面板

### 钱要有分量

薪资尺度定在「一名 80 分选手年薪 $265K」，不是随手拍的，是按**薪资占俱乐部收入的比例**倒推的：

| 薪资基数 | 一级平均薪资 | 净额 | 占收入 | 亏损队 | 一年结余能买几个顶级球员 |
| --- | --- | --- | --- | --- | --- |
| 15000（旧） | $0.75M | +$1.71M | 22% | 3/48 | **4.1 个** ← 钱没有意义 |
| **33000（现）** | **$1.65M** | **+$0.81M** | **49%** | **11/48** | **1.9 个** |
| 45000 | $2.26M | +$0.20M | 67% | 22/48 | 0.5 个 ← AI 转会预算被压干 |

同一次改动里次级系数从 0.30 降到 0.14，把挑战者的薪资**留在原处**——不这么做，
刚修好的次级破产问题会原样回来（当时 29 支里 20 支转负）。这也更接近真实：挑战者的薪水是
VCT 的零头，不是三成。

两个常数必须同步：`scripts/build_world.py` 的 `SALARY_BASE` / `TIER2_WAGE`，和
`src/engine/player.ts` 里同名的两个——前者决定新世界的薪资表，后者是选手每次谈判时的要价。

### 训练是有代价的，也是有回报的

八个存档 × 五个赛季，同一支队，只改训练策略：

| 策略 | 下课 | Stage 2 平均名次 | 伤病/赛季 | 开局阵容 5 年能力变化 |
| --- | --- | --- | --- | --- |
| 全员休息 | 0/8 | 2.4 | 1.9 | **+3.8** |
| 疲劳 >62 才休息 | 4/8 | 2.5 | 3.2 | +8.4 |
| **疲劳 >40 就休息** | **1/8** | **1.8** | 2.4 | **+9.6** |

最优解在中间：**练，但别练到人垮**。一味休息安全却停滞，一味硬练伤病翻倍、成绩反而更差。
训练页的「自动分配」按这个结论走（体能 45 以上自动改休息，其余按位置重点分配）——
它原来是 70 才休息、而且练最短板，等于把你放在上表最差的那一档。

改完之后，认真经营应该赢过什么都不做，实测确实如此（JDG 六个存档 × 五赛季）：

| | 下课 | Stage 2 平均 | 伤病/赛季 | 5 年能力 |
| --- | --- | --- | --- | --- |
| **认真练 + 控体能** | **1/6** | **3.9** | 2.5 | **+9.3** |
| 完全摆烂 | 3/6 | 5.0 | 1.3 | +5.1 |

在此之前是**反过来的**：摆烂的活得更久。原因是董事会的信任摆动不对称——刚好达标 +6，
差一名 −8，于是一支「基本符合预期」的球队每个赛段净跌 1 点，慢慢就被磨到下课；
而把阵容练强反而会让董事会按新评分抬高要求，越练越难达标。差一名现在是 −5。

### 一个赛季里会发生什么

| 事件 | 频率 | 由什么决定 |
| --- | --- | --- |
| 伤病 | 休息为主 **2.1 人次/赛季**，满额训练 **3.3** | 每周每人 `0.5% + (体能−40)×0.12%`，27 岁以上每岁再 +0.2%；比赛后按当场体能另算一次 |
| 退役 | 全世界 **4.8 人/赛季** | 赛季末：34 岁以上 45%、32+ 20%、30+ 6% |
| 转会传闻 | 2.7 次/赛季 | 只有能力 ≥ 队伍评分 −2 的人才会被盯上，且对方必须真的缺这个位置 |
| 生日 | 4 次/赛季 | Liquipedia 的真实生日，全联盟 366 人有 |
| 生涯里程碑 | 2.4 次/赛季 | 生涯地图数跨过 100/250/500/750/1000/1500/2000 |
| 状态爆发 / 低迷 | 8.6 / 0.2 次/赛季 | 状态跨过 83 或 59（实测分布 p50=69、p95=83、p5=59） |
| 要求加薪 | 0.4 次/赛季 | 身价比现薪高出 30% 以上，且 120 天内没提过 |
| 更衣室矛盾 | 输球后触发 | 一人打得好另一人打得差，且会滚雪球 |

**世界会慢慢变少**：本作不生成虚构新人，所以退役的人不会有人补上——五个赛季从 515 人
掉到 491 人。这是"不编造真人"这条规则的直接代价，退役概率因此定得保守。

### 输了要知道为什么

每场比赛（我方参与的）会记录**双方各自的强弱分解**，赛后在比赛详情里按差距从大到小列出：
个人能力、地图熟练度、团队默契、位置搭配、指挥、教练战术、道具、以及**赛前四条滑杆
在进攻端/防守端分别值多少**。每一项还写明「怎么调整」——地图差就去跑图，默契差就双排练，
战术滑杆拖过头就调回来。

这些是**模拟器判定胜负时用的数值本身**，不是事后编的解释。数值只决定每回合胜率，
所以账面占优照样可能输——那种情况面板会直接说出来，提示去看状态、体能或运气。

### 比赛模拟的标定

回合模型按真实 VCT 统计区间标定，跑完整赛季后的联赛平均值：

| 指标 | 本作 | 真实 VCT |
| --- | --- | --- |
| ACS 平均 | ~200 | ~200 |
| K/D 平均 | ~0.99 | ~1.00 |
| ADR 平均 | ~137 | ~135 |
| Rating 平均 | ~0.99 | ~1.00 |
| 顶尖选手 K/D | ~1.6 | ~1.4–1.5 |

回合胜率对实力差的敏感度被刻意压低——真实 VCT 里最强的队面对全联盟也只能拿下约六成
回合，而不是压倒性碾压。

## 游玩数据

线上版本会记录**这个游戏是怎么被玩的**——不记录**是谁在玩**。

- **身份**是浏览器首次打开时自己生成的一串随机字符，存在 localStorage。**服务端从不记录、不存储 IP 地址**（IP 只在内存里用于限流，用完即弃）。清掉网站数据就会被当成新用户，同一台手机上的两个人算一个人——问「有没有人再回来」，这比 IP 准得多：国内运营商动辄几百人共用一个出口 IP，同一个人一晚上还会换好几个。
- **时长**只累计**确认活跃**的分钟数：页面在前台、且最近三分钟内有过操作才计时。标签页挂着过夜不算。累计值每几分钟上报一次而不是只在关闭时报——iOS Safari 经常不触发 `pagehide`，只认结束事件会把这批用户的时长整段丢掉。
- **重发不会重复计数**。`sendBeacon` 没有回执，弱网手机会把同一批事件再发一次；每条事件带一个会话内序号，数据库上有唯一约束，重发是空操作。
- **入库端点是公开的**（游戏没有账号），所以按"互联网一定会找到它"来写：请求体、单批条数、属性个数、字符串长度、每分钟频次全部有上限，事件名是白名单——不在名单里的直接丢弃，没人能往表里灌自己的词汇。
- **不采集**：IP、精确地理位置、UA 明文、页面停留时长、任何游戏之外的行为。只有链接来源的**域名**（微信和小红书的内置浏览器通常会把它抹掉，所以大多数是空的）。

没有 `DATABASE_URL` 时（比如本地跑），统计整体关闭，游戏行为和以前完全一样。数据库挂了或连不上也一样——**统计绝不能拖垮游戏**，这条实测过。

后台在 `/admin?token=…`，口令存在 Railway 环境变量 `ANALYTICS_TOKEN` 里，不在代码库中。口令不对一律返回 404 而不是 401——会承认自己存在的入口，别人就会再回来试。

| 文件 | 职责 |
| --- | --- |
| `src/engine/telemetry.ts` | 浏览器端：匿名 ID、会话、活跃计时、批量上报 |
| `analytics.js` | 事件白名单、载荷净化、限流、口令校验、建表 |
| `stats.js` | 后台的全部 SQL，每个指标都写明「看了它你会改什么」 |
| `dashboard.js` | 后台页面，单文件无依赖 |

## 队名的写法

密集的地方（积分榜、赛程、赛果、对阵图、转会列表、顶栏）一律用**简称**：EDG、XLG、KBG，
鼠标悬停显示全称。正式场合保留**全称**：比赛详情标题、新闻、执教邀请与合同、选队界面。
搜索**两种都认**——输 `EDG` 或 `EDward` 都能找到他们的选手。

## 新手引导：一个模拟的一天

先用两屏讲清基本机制（你负责什么、行动力、回合、董事会），然后进入一个
**模拟的 12 月 31 日**，手把手走一遍：

- **要你点的标签自己点**——高亮那一个，其余变暗且点不动
- **训练页真的排一次**：选一项团队训练 + 给一名选手定训练重点，做完才继续
- **转会页真的问一次价**：按俱乐部找人、发出问询
- **积分榜与财务只作说明**——董事会看哪个数字、钱从哪来到哪去
- 最后回总览**按下推进**，结束这一天

整段结束后**游戏状态完整回滚**（引导开始前做过快照），所以这一天是白送的，
练手不花任何代价。存档页可以重播。

## 回合节奏

赛季中**一天一回合**；距下一场正式比赛还有 7 天以上时（季前、休赛期、赛段之间），
**一回合变成一周**，行动力仍是 3 点。手动一天一天点也不会额外刷新行动力——
预算属于回合，不属于日期。

## 行动力

**赛季中一天一回合、2 点；空档期一周一回合、4 点。** 第一版是不分阶段的每天 3 点，
方向正好反了——赛季里转会窗关着、商务又会影响赛前状态，三点用不完；而空档期窗口开着、
所有谈判都能做，一周却也只有三点。现在按"实际有多少事可做"给。

**只有对外的事花点数**：
提交/答复报价、接商务活动、谈赞助、办活动、签直播、约训练赛、聘教练、升级设施，各 1 点。
**首发、战术、训练安排不花点数**——不该为了省点数而故意排一个更差的首发。

配套的是让每件事都有时限（邀约会过期、报价要在几天内答复、训练赛只在赛前有用），
所以三点花在哪里是**分诊**，不是偏好。行动力常驻右上角。

## 训练与行动的结算节奏

推进是按天的，但训练按**周**结算（`day % 7 === 0`）。个人专项和团队训练都在那一刻生效一次，
中途改动只影响下一次结算，不会重复计算。训练面板会显示距离下次结算还有几天。

## 数据抓取说明

抓取脚本严格遵守 [Liquipedia API 条款](https://liquipedia.net/api-terms-of-use)，
而且是**代码强制**而非口头承诺：

- 所有请求走统一节流器，**≥ 2.5 秒/次**（条款要求 ≥ 2 秒）
- **`action=parse` 被直接禁用**（条款限 30 秒/次）。改用 `action=query` 一次查 50 个页面，
  340 名选手只需 7 个请求
- 收到 429 **立即中止并保存已有结果**，绝不重试硬撞
- 携带标识性 User-Agent（含联系方式）+ gzip
- 结果全部落盘缓存，重跑只补缺失的部分

请不要调低 `MIN_INTERVAL`。违规会导致 IP 临时封禁，反复触发会变成永久封禁
（本项目开发时就踩过一次，是用 `action=parse` 每 2.2 秒请求造成的）。

次级战队的**教练、IGL 与生日**由 `scripts/fetch_liquipedia.py` 补齐——同一套合规客户端
（≥2.5 秒/次、禁用 `action=parse`、429 立即中止），把 Challengers 的选手与俱乐部一并纳入
批量查询。补完后：真实生日 318→376，真实教练 51→67，次级战队缺教练 25→9。

Challengers 数据由 `scripts/fetch_vlr_challengers.py` 抓取：先读各国 Challengers 赛事页拿到
参赛队与名单，再读**赛事统计页**一次性拿到该赛事所有选手的真实数据——一个联赛一个请求，
而不是一名选手一个请求（省下约 250 次请求）。只有统计页为空的联赛（如中国大陆的
China National Tournament）才回落到逐个选手页。次级选手的能力值与一级选手在**同一个
百分位池**里换算，所以他们较弱是被量出来的，不是被手动扣分扣出来的。

### 次级数据要先折算成一级，再进池子

同一个百分位池有个隐含假设：250 ACS 在哪打出来都是 250 ACS。但次级战队的数据大部分是
和次级战队打出来的。不折算的话 NRG Academy 会被算成 **90**——比 VCT 美洲所有队都高。

折算系数不是拍的，是用**同一个人的两份数据**量出来的（`scripts/calibrate_tier.py`）：

| | 比较对象 | 样本 | R | ACS | K/D |
| --- | --- | --- | --- | --- | --- |
| 第一步 | 同一人的 Challengers 数据 vs VCT 数据 | 72 人 | ×0.881 | ×0.906 | ×0.835 |
| 第二步 | 从没打过 VCT 的人：生涯数据 vs 纯 Challengers 数据 | 336 人 | ×0.944 | ×0.938 | ×0.925 |
| 合计 | 生涯数据 → VCT 等价 | | **×0.831** | **×0.850** | **×0.773** |

第二步是因为 vlr 的生涯页把公开赛、三级赛事也算进去了，所以生涯均值比 Challengers 本身
还虚高一截。折算只作用在**生涯数据的那一半**：一名选手累计 VCT 回合越多，他的成绩就越是
在一级对手身上打出来的，折算权重线性退到 0（600 回合 ≈ 一个赛段加季后赛）。hezacoil 只有
190 个 VCT 回合却被当成 2754 回合的定论，就是这样修掉的。

系数偏保守：能被一级队调上去的次级选手，本来就是转化最好的那批，所以真实差距只会更大。

折算后：美洲次级最强从 90 掉到 77（VCT 第 10 名的位置），中国次级最强 71，全部低于该区
所有 VCT 战队。剩下评分还高的次级队（M80、REJECT、Sangal）阵中都是有真实 VCT 出场记录的
老将——他们不折算，因为他们的数据本来就是打一级对手打出来的。

**关于选手履历**：Liquipedia 没有公开的 timeline 或 LPDB 接口（wiki 侧只有标准 MediaWiki 模块，
无 `cargoquery`/`ask`/`lpdb`），但 `action=expandtemplates` 可以直接展开 `{{TeamHistoryAuto}}`，
而这个模板背后读的正是 LPDB。它还接受 `|player=` 参数，因此一次请求可以展开 25 名选手——
**545 名选手只用了 15 个请求**，而不是 545 个页面。注意 LPDB 查询区分大小写而 MediaWiki 会把
页面名首字母大写，`player=basic` 返回空、`player=Basic` 才有数据。

**关于 vlr.gg**：`robots.txt` 只禁止 `/search/auto` 与 `/rr/`，其余允许抓取，
但**没有公布任何速率上限**——开发中触发过一次 IP 限流，是短时间内约 1000 次请求造成的。
因此脚本同样走强制节流（≥ 3 秒/次），遇到 429 立即停止并保存进度。没有公布上限
不等于没有上限，宁可慢。

**关于付费 API**：Liquipedia 另有商业化的 LiquipediaDB API，但 Basic / Premium 档位
目前不可用，只剩 Enterprise 自定义报价，面向商业伙伴。本项目用免费的 MediaWiki API
已经拿到 94% 的生日与全部教练/IGL，没有申请必要。
