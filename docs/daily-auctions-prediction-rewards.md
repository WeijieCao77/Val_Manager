# 日常资源、竞拍快捷入口与冠军赛预测奖励

2026-09-19：签到金币 300 → 375；五种日常任务金币分别为 300、400、250、325、375（均比原来增加 25%）。清完当日任务奖励 2 个试训包。已领取的签到和任务不会重复发放或追补；连签第 3、6、7 天的额外卡包不变。

交易页顶部的“我参与的竞拍”读取 `/api/market/participating`。它按账号历史出价查仍开放、未到期的拍卖，每页 60 张，按挂牌 ID 倒序；重复出价只显示一张。被超价退款不移除，成交、撤回或到期则移除。该接口只读，不负责结算；价格、最低下一口、是否领先与货架使用同一个实时查询。客户端刷新当前页，不会因为货架筛选而隐藏参与过的拍卖。

## 预测奖励

每组仅领取最高一档，依据保存的第一、第二名，不要求此前每一场胜负都猜中：

| 命中情况 | 奖励 |
| --- | --- |
| 两队和名次全对 | 2 个十连包 |
| 一队和名次对 | 1 个十连包 |
| 两队都晋级但名次颠倒 | 5 个选拔包 |
| 仅一队晋级、名次错误 | 3 个选拔包 |
| 无晋级队命中 | 无奖励 |

`predict_claim` 只接受赛事和小组标识。服务端计算奖励，在现有账号事务内发包并保存 `predict[event][group].claimedAt`；重复提交、跨设备重试以及客户端提交赛果、奖励或领取标记都不能额外发包。

## 赛果发布

`src/data/predictResults.json` 是随服务端构建发布的赛果清单，目前为空，不能用模拟比赛或玩家上报结果填充。

每组比赛结束后，核实正式最终名次，再在 `champions-2026` 下添加对应组键（A/B/C/D）。该组对象需要三个字段：`first`（正式第一名队伍 tag）、`second`（正式第二名 tag）、`confirmedAt`（实际确认时间的 Unix 毫秒整数）。两队必须属于该组且不能相同，确认时间必须晚于该组决胜局开始时间。

发布前运行 `npm run build` 和预测相关检查，随后部署。到确认时间且新版服务端上线后，玩家在预测页主动领取；每组独立结算，不必等其他组结束。赛果一旦有人领取，不应直接改写为另一组名次；纠错应单独评估已发奖励。

验证：`scripts/check_prediction_rewards.ts` 覆盖全部档位、无赛果/未来赛果/无效赛果、锁定预测、存档迁移、客户端伪造、API 并发领取和请求重放；`scripts/check_market_participating.ts` 覆盖真实出价→被超→再次出价、去重、跨账号隔离、关闭/过期拍卖与分页；`scripts/check_checkin.ts` 覆盖增发金额和日常卡包只发一次。新检查已加入全量 CI 清单。
